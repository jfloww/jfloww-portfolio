# Project Summary

**Purpose:** Build a responsive portfolio that presents projects clearly and lets content be updated without changing page layouts.

**My role:** Designed and implemented the content model, project pages, responsive UI, and localization flow.

## Core Functionality

- MDX-based project and post content with frontmatter metadata
- Project list/detail pages with image galleries
- Korean and English routes with shared UI components
- Dark mode and responsive navigation

## Tech Stack & Why

- **Next.js App Router** — Static generation for content pages and file-based routing for the portfolio structure.
- **TypeScript** — Typed content metadata and component contracts.
- **Tailwind CSS** — Consistent responsive styling through reusable utility patterns.
- **MDX + gray-matter** — Separates page content from UI code while retaining structured metadata.

## Architecture & Flow

`MDX file → content loader → typed metadata/content → static project page → optional client image slider`

1. Each project is stored as an MDX file with frontmatter.
2. The loader validates and normalizes metadata before list and detail pages consume it.
3. Next.js statically generates the detail page; only interactive UI, such as the slider and navigation menu, runs on the client.

## Design Decisions

- **Content Repository pattern** — A single content loader abstracts file access, parsing, visibility, and localized selection so pages do not depend on filesystem details.
- **Server/Client component split** — Content pages render on the server for fast delivery; isolated client components handle interaction only where needed.
- **Reusable template components** — Shared header, footer, cards, and detail layouts keep visual behavior consistent as content grows.

## Result

The portfolio supports adding a project by creating one MDX file and its assets, without creating a new page component. The structure keeps content maintenance separate from layout and interaction code.
