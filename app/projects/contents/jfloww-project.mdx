# Project Summary

**Purpose:** Build a portfolio where Projects and development Posts can grow without adding a new page component for every entry.

**My role:** Designed and implemented the content model, Next.js routes, responsive UI, localization flow, theme behavior, and Contact endpoint.

## Core Functionality

- MDX-based Project and Post content with typed frontmatter
- Static list and detail routes
- English and Korean content selection with fallback
- Responsive continuous-surface layout with light and dark themes
- Post filtering and locale-specific summaries
- Validated Contact form with email delivery

## Architecture

```text
MDX -> content loader -> normalized metadata -> locale selection -> static page
```

Projects and Posts share one loader for file discovery, visibility, sorting, localization, and static route generation. Content pages render on the server; client code is limited to navigation, theme, filtering, and form interactions.

Project images are used as list covers. Detail pages start directly with the written explanation instead of repeating screenshots in a slider.

## Result

New content can be published by adding an MDX file and assets while the list and detail layouts remain unchanged. The same content feeds the Home page, archive pages, and localized static routes.
