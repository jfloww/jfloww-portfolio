## 프로젝트 개요

`Picking Up`은 내가 실제로 매일 쓰기 위한 to-do 플랫폼으로 시작한 프로젝트다.

처음 목표는 단순했다. 할 일을 빠르게 추가하고, 오늘 해야 할 일을 보고, 완료 처리하고, 브라우저가 바뀌어도 내 데이터가 유지되는 앱을 만드는 것. 처음부터 협업, AI, 반복 일정, 알림 같은 기능을 넣기보다는, 매일 쓰는 기본 흐름이 먼저 제대로 동작하는지를 확인하는 쪽에 집중했다.

## 제품 방향

기술 방향은 web-first로 잡았다. 먼저 데스크톱 브라우저에서 쓸 수 있는 Next.js 앱을 만들고, 작은 브라우저 창과 모바일 브라우저에서도 깨지지 않게 만든다. 그 다음 필요하면 PWA로 확장하고, 그래도 부족하면 iPhone 앱을 따로 만든다.

모바일 앱을 처음부터 만들기보다, 하나의 Django API를 중심에 두고 웹과 미래의 모바일 클라이언트가 같은 데이터를 쓰는 구조를 선택했다.

```text
Next.js frontend
        |
        v
Django REST API
        |
        v
Oracle Database on OCI
```

## 기술 스택

- Frontend: Next.js, React, TypeScript
- Backend: Django, Django REST Framework
- Auth: JWT, HTTP-only cookie
- Database: Oracle Database on OCI
- Local development DB: SQLite fallback
- Hosting direction: Vercel + OCI VM

프론트엔드는 feature-based 구조를 사용한다. 백엔드는 인증, 권한, API contract, task data, migration을 책임진다. production database는 Oracle Database on OCI를 목표로 한다.

## 설계 기준

이 프로젝트에서 중요하게 잡은 기준은 두 가지다.

첫 번째는 작게 시작하되 나중에 갈아엎지 않을 구조를 만드는 것이다. 그래서 task data 접근은 repository interface 뒤에 숨기는 방향으로 설계했다. 지금은 localStorage로 task를 저장하지만, 나중에 Django API로 바꿔도 UI 전체를 다시 뜯지 않도록 하기 위해서다.

두 번째는 보기 좋은 앱보다 실제로 쓰는 앱을 만드는 것이다. 랜딩 페이지와 로그인 화면은 미니멀하게 정리했지만, 핵심은 결국 `/app` 안의 task workspace다.

## 핵심 기능 방향

현재 만들고 있는 `/app`은 단순한 task list가 아니라 Daily, Weekly, Monthly, Yearly view를 가진 calendar형 to-do workspace다.

핵심 컨셉은 `zoomed-out context, focused present`다. 전체 기간의 맥락은 보여주되, 지금 집중해야 할 날짜, 주, 달을 더 선명하게 보여주는 방식이다.

예를 들어 Weekly view에서는 한 달 전체를 보여주되 현재 주를 강조한다. Daily view에서는 한 주 전체를 보여주되 선택된 하루에 집중한다. Monthly view는 1년의 12개월을 보여주고, Yearly view는 연 단위 목표를 다룬다.

## 현재 상태

현재 개발은 Phase 1의 후반부에 있다. 프로젝트 foundation, 인증, 디자인 시스템, 랜딩/auth 화면, task calendar의 핵심 로직과 일부 view까지 구현된 상태다.

다음 목표는 `/app`의 task calendar를 완성하고, 이후 Django task API와 연결하는 것이다.
