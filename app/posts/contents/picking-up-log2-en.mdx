## Goal

By the first log, tasks could be stored and displayed by day and week. This round of work was about turning that calendar into a screen I could use to plan a real day.

It needed a quick way to schedule and move time, rules for recurring work, and a Weekly view that made progress easy to read. From July 17 through July 23, I adjusted Daily and Weekly several times after using the interactions directly.

## Sketch

Daily would focus on one date's timeline and agenda. Weekly would show the distribution of work across seven days.

```text
Daily
  ├─ Timeline
  │    ├─ All-day tasks
  │    └─ Timed tasks
  └─ Agenda
       ├─ All Day To-Do
       ├─ Next Up
       └─ Done Today

Weekly
  ├─ completed / total + progress
  └─ Sun | Mon | Tue | Wed | Thu | Fri | Sat
```

The task model gained the fields needed to represent a schedule.

```ts
time?: string;
durationMinutes?: number;
background?: boolean;
repeatWeekdays?: number[];
repeatSourceId?: string;
```

## Plan

1. Add time and duration to tasks — the list needed to represent actual scheduled work.
2. Add drag-to-schedule to Daily — repeatedly typing times was too slow for adjusting a day.
3. Keep recurrence in the existing task model — a separate Routine area was unnecessary.
4. Rebuild Weekly as a one-week dashboard — the current week mattered more than a compressed month.
5. Share one task-detail drawer — Daily and Weekly should use the same editing path.
6. Tune visual density last — spacing problems were easier to judge with working interactions.

## Issues During Development

### Dragging was unreliable in the seven-day Daily view

The first Daily view showed a seven-day window around the selected date. The context was useful, but a drop near a neighboring date could change focus.

Instead of adding more drag exceptions, Daily was changed to a two-column layout for one date. Previous and Next now move one day at a time.

```text
All-day task ──drag──> hour rail      = set a time
Timeline chip ──drag──> new position  = change the time
Timeline chip ──drag──> All-day       = clear the time
```

The rail snaps to 15-minute increments and auto-scrolls near its edges. The time input remains available for the same keyboard-accessible action.

### A growing All-day area pushed the timeline off screen

On short viewports, the All-day area and timeline grew together and made the whole planner scroll. A `ShrinkStack` lets the timeline shrink to a minimum height as All-day content grows, with scrolling contained inside each panel.

During the later Focus Planner pass, the timeline and agenda settled into a 60/40 layout and task details moved into a right-side drawer.

### Routine occurrences could pile up like ordinary unfinished tasks

Weekday recurrence was implemented with an anchor that creates one occurrence when a matching date arrives. The new task copies the title, time, and memo at that point.

```text
Routine anchor
  -> check whether today matches
  -> create only if no occurrence exists
  -> keep the anchor id in repeatSourceId
```

Applying normal rollover to these occurrences would keep missed routine work in the current backlog. Routine occurrences were excluded from rollover and are not persisted before their date. Weekly shows dimmed previews for upcoming occurrences instead.

### Overlapping tasks covered each other

The first layout placed tasks side by side only when their start times matched. Once duration existed, different start times could still occupy the same interval.

```text
08:00 ┌ background: Work ┐  ┌ Task A ┐
09:00 │                  │  ├ Task B ┤
10:00 │                  │  └────────┘
```

Column assignment moved from start-time grouping to interval-overlap calculation. Tasks without duration use a nominal 30 minutes. Long blocks that should not compete with ordinary tasks can render in a separate `background` lane.

## Completed Flow

As of July 23, this workflow was available:

```text
open Daily
  -> add an All-day task
  -> drag it onto the timeline
  -> set duration and priority
  -> check subtasks
  -> edit in the drawer and press Done
  -> read weekly progress in Weekly
```

The completed work included:

- 15-minute drag-to-schedule with auto-scroll;
- task duration and timeline chips with matching height;
- All-day, Next Up, and Done Today agenda groups;
- weekday routines and the next three expected dates;
- Weekly progress with seven day columns;
- Monthly → Weekly → Daily drill-down;
- one task-detail drawer shared by Daily and Weekly;
- a background lane and interval-overlap layout;
- timeline checkboxes and a full-chip click target.

## Improvements and Notes

- Task persistence still uses the localStorage repository.
- Recurrence currently supports weekdays only.
- Saving several drawer fields at once can be simplified further.
- The next step is a task API that makes the same data available outside one browser.
