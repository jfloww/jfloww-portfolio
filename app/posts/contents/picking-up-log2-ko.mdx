## 목적

첫 번째 로그까지는 task를 날짜와 주 단위로 저장하고 보여줄 수 있었다. 이번 작업의 목적은 그 달력을 실제로 하루를 계획할 수 있는 화면으로 바꾸는 것이었다.

시간을 정하고 다시 옮기는 과정, 반복되는 일을 관리하는 방식, 한 주의 진행 상황을 읽는 화면이 필요했다. 7월 17일부터 23일까지 Daily와 Weekly를 여러 번 사용해보며 구조를 조정했다.

## 스케치

Daily는 한 날짜의 timeline과 agenda에 집중하고, Weekly는 일주일의 분포를 확인하는 화면으로 역할을 나눴다.

```text
Daily
  ├─ Timeline
  │    ├─ All-day tasks
  │    └─ Timed tasks
  └─ Agenda
       ├─ All Day To-Do
       ├─ Next Up
       └─ Done Today

Weekly
  ├─ completed / total + progress
  └─ Sun | Mon | Tue | Wed | Thu | Fri | Sat
```

task에는 일정 표현에 필요한 필드를 추가했다.

```ts
time?: string;
durationMinutes?: number;
background?: boolean;
repeatWeekdays?: number[];
repeatSourceId?: string;
```

## 계획

1. task에 시간과 duration을 추가한다 — 목록과 실제 일정의 차이를 줄이기 위해서였다.
2. Daily에 drag-to-schedule을 붙인다 — 시간을 계속 입력하는 방식은 일정 변경에 불편했다.
3. 반복 일정을 기존 task model에 넣는다 — 별도 Routine 화면을 만들 필요가 없었다.
4. Weekly를 한 주 dashboard로 바꾼다 — 한 달 전체보다 현재 주의 상태를 먼저 보고 싶었다.
5. task detail을 drawer로 통일한다 — Daily와 Weekly에서 같은 편집 흐름을 사용하기 위해서였다.
6. 마지막에 시각 밀도를 조정한다 — 기능이 동작한 뒤 실제 화면에서 답답한 부분을 확인하려 했다.

## 만들면서 생긴 이슈

### Daily의 7일 화면에서 drag가 자주 빗나갔다

초기 Daily는 선택한 날짜 앞뒤까지 포함한 7일 window였다. 주변 일정은 잘 보였지만 task를 rail에 놓다가 옆 날짜를 건드리면 focus가 바뀌었다.

drag 예외를 계속 추가하는 대신 Daily를 한 날짜만 보여주는 2-column layout으로 바꿨다. 이전과 다음 버튼도 하루씩 이동하도록 맞췄다.

```text
All-day task ──drag──> hour rail      = 시간 지정
Timeline chip ──drag──> new position  = 시간 변경
Timeline chip ──drag──> All-day       = 시간 해제
```

rail은 15분 단위로 snap하고, 위아래 끝에서는 자동으로 scroll한다. time input도 남겨 키보드로 같은 작업을 할 수 있게 했다.

### All-day task가 늘면 timeline이 화면 밖으로 밀렸다

화면 높이가 짧은 환경에서는 All-day 영역과 timeline이 함께 커지면서 planner 전체가 길어졌다. `ShrinkStack`을 만들어 All-day가 커질 때 timeline이 최소 높이까지 줄어들고, 각 panel 안에서만 scroll하도록 바꿨다.

이후 Daily를 Focus Planner 형태로 정리하면서 timeline과 agenda를 60/40 비율로 배치하고, task detail은 오른쪽 drawer로 옮겼다.

### 반복 task가 일반 미완료 task처럼 쌓일 수 있었다

요일 반복은 anchor task가 해당 날짜에 도착했을 때 occurrence를 하나 만드는 방식으로 구현했다. 생성된 occurrence는 그 시점의 제목, 시간, 메모를 복사한 독립 task다.

```text
Routine anchor
  -> 오늘이 선택된 요일인지 확인
  -> occurrence가 없을 때만 생성
  -> repeatSourceId로 anchor 기록
```

이 occurrence까지 일반 rollover 대상에 넣으면 놓친 routine이 계속 현재 목록으로 따라왔다. routine occurrence는 rollover에서 제외하고, 아직 도착하지 않은 날짜에는 저장하지 않기로 했다. Weekly에서는 예정된 occurrence만 흐리게 미리 보여준다.

### 시간이 겹치는 task가 서로 가렸다

처음에는 시작 시간이 같은 task만 나란히 배치했다. duration이 추가되면서 시작 시간이 달라도 실제 구간이 겹칠 수 있었다.

```text
08:00 ┌ background: Work ┐  ┌ Task A ┐
09:00 │                  │  ├ Task B ┤
10:00 │                  │  └────────┘
```

배치 계산을 시작 시각 비교에서 interval overlap 계산으로 바꿨다. duration이 없는 task는 30분으로 계산했다. 긴 업무 시간처럼 다른 일정과 경쟁하지 않아야 하는 task는 `background` lane에 따로 표시했다.

## 완성된 흐름

7월 23일 기준으로 다음 작업을 할 수 있었다.

```text
Daily 진입
  -> All-day task 추가
  -> timeline으로 끌어 시간 지정
  -> duration과 priority 설정
  -> subtask 확인
  -> drawer에서 수정 후 Done
  -> Weekly에서 일주일 진행률 확인
```

추가된 기능은 다음과 같다.

- 15분 단위 drag-to-schedule과 auto-scroll
- task duration과 실제 높이의 timeline chip
- All-day, Next Up, Done Today agenda
- 요일 기반 routine과 다음 세 번의 예정 날짜
- Weekly 진행률과 일곱 개 day column
- Monthly → Weekly → Daily drill-down
- Daily와 Weekly가 공유하는 task detail drawer
- background lane과 interval overlap layout
- timeline checkbox와 전체 chip click 영역

## 개선점과 노트

- task 저장은 여전히 localStorage repository를 사용한다.
- 반복 규칙은 요일 단위만 지원한다.
- drawer에서 여러 필드를 한 번에 저장하는 방식은 더 단순하게 만들 여지가 있다.
- 다음 작업은 task API를 만들고 browser 밖에서도 같은 데이터를 사용하는 것이다.
